## 2. Відповідь на контрольне запитання

**Запитання:** `Що таке рекурсія?`

**Відповідь:**

Рекурсія - це спосіб організації алгоритму, за якого функція викликає сама себе.
Складну задачу розбивають на підзадачі того ж типу, поки не буде досягнуто такого простий випадок, що його розв'язок відомий одразу.

Кожна рекурсивна функція складається з 2 частин:
* Базовий випадок - умова, за якої функція повертає результат без нового виклику самої себе. Він зупиняє рекурсію.
* Рекурсивний випадок - виклик функції з іншими (спрощеними) аргументами, які наближають задачу до базового випадку.

Обов'язкова умова коректної роботи: наявність базового випадку і гарантований рух до нього при кожному виклику. Інакше рекурсія буде нескінченною: кожен виклик займає місце в стеку викликів, і Python видасть RecursionError: maximum recursion depth exceeded (стандартний ліміт - близько 1000 викликів, його можна дізнатися через sys.getrecursionlimit()).

Приклад:
def factorial(n: int) -> int:
    if n <= 1:                      # базовий випадок
        return 1
    return n * factorial(n - 1)     # рекурсивний випадок: n зменшується

Виклик factorial(3) розгортається так: 3 * factorial(2) → 3 * 2 * factorial(1) → 3 * 2 * 1 = 6.

Порівняння з ітерацією: рекурсія робить код коротшим і природнішим для задач зі самоподібною структурою (розбиття, перебір комбінацій і тд), але використовує пам'ять стека і може бути повільною через повторні обчислення. 
Цю проблему можна вирішити кешуванням (functools.lru_cache).

У моїй роботі: функція best_purchases рекурсивно розв'язує задачу про рюкзак: для кожного товару розглядається два варіанти - пропустити або купити. 
Базовий випадок: index == len(items) or left <= 0 (товари закінчились або бюджет вичерпано). 
Кожен виклик збільшує index, тож рекурсія гарантовано завершується. 
Для ефективності використано lru_cache, щоб не рахувати однакові підзадачі повторно.
